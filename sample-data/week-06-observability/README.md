# Week 06 - Gateway Observability Dataset

This folder contains deterministic synthetic cases for ClaimFlow AI's Week 6 AI gateway and observability layer.

The goal is to prove that model calls are governed and traceable without depending on real provider failures.

```txt
synthetic gateway case
-> callModelThroughGateway
-> AiCallLog row
-> status / failure type / latency / cost / versions recorded
-> Week 6 eval report
-> eval dashboard later
```

## What this dataset proves

- model timeouts become retryable failures
- invalid JSON becomes a failed gateway call
- provider errors become retryable failures
- cost limits block calls
- latency spikes are visible even when calls succeed
- prompt-version regressions can be represented as governance failures
- eval score drops can be represented as regression failures
- missing trace IDs are generated by the gateway
- missing model versions are blocked

## Gateway case contract

Each case has:

```txt
manifest.json  - human-readable case identity
input.json     - synthetic gateway input and fake provider behavior
expected.json  - expected status, failure type, retryability, and dashboard fields
README.md      - explanation for reviewers
```

## Important behavior

The missing trace ID case should pass. The gateway is expected to generate a trace ID.

The latency spike case should also pass as a successful call with a warning-style failure type. A slow but valid response is observable, not automatically failed.
