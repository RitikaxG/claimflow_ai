# Auto Insurance v1 Dataset

This is the Week 1 ClaimFlow AI dataset for auto insurance claim intake.

It tests the first product workflow:

```txt
PDF / email text
→ AI extraction
→ structured claim JSON
→ deterministic validation
→ COMPLETED or NEEDS_REVIEW
```

This dataset used to be described by the top-level `sample-data/README.md`. Now that Week 2 has its own review-failure dataset, this README should live beside the Week 1 dataset itself.

## What this dataset tests

This dataset checks whether ClaimFlow AI can extract and validate the core auto-insurance claim fields:

- document type
- policy number
- claim number
- insured name
- claimant name
- vehicle registration number
- incident date
- incident location
- loss type
- estimated repair cost
- currency
- FIR number when relevant
- supporting document flags

## Folder purpose

| Folder / file | Purpose |
|---|---|
| `source-docs/` | Public/reference and synthetic documents used for Week 1 extraction tests |
| `expected-extractions/` | Gold JSON matching `ClaimExtractionSchema` |
| `expected-validations/` | Gold validation output matching `ClaimValidationResultSchema` |
| `actual-extractions/` | Exported model outputs from local runs |
| `actual-validations/` | Exported deterministic validation outputs from local runs |
| `eval-results/` | Markdown + JSON reports generated by the Week 1 eval script |
| `eval-manifest.json` | List of samples evaluated by Week 1 eval tooling |
| `field-matrix.md` | Explains why each schema field exists |

## How to run Week 1 eval

From the repo root:

```bash
bun run eval:week1:export
bun run eval:week1
```

`eval:week1:export` exports actual extraction and validation outputs.

`eval:week1` compares actual outputs against the expected gold files and writes reports under `eval-results/`.

## Relationship to Week 2

Week 1 verifies extraction and validation correctness.

Week 2 builds on this by checking what happens after validation returns `NEEDS_REVIEW`:

```txt
NEEDS_REVIEW
→ ReviewTask
→ reviewer action
→ ReviewDecision
→ ReviewEvent
```

Week 2-specific failure and review-decision cases live in:

```txt
sample-data/week-02-review-failures/
```

## Safety

All synthetic data must remain fake and repeatable.

Do not commit real customer data, real claim documents, real policy numbers, API keys, or large raw datasets.
